# 资源存储迁移方案（已完成）

本方案的目标已经落地：主仓库不再跟踪或生成本地采样目录，外部音库作为独立、自描述、可校验的资源包发布。

## 当前边界

主仓库只包含框架、资源协议、工程和远程目录加载器。官方与团队音库使用相同的 `momo.remote-sound-library/v1` 协议；每个 `index.json` 都包含音库身份、资源定义、完整音频依赖、来源和许可。

用户可以在资源库中下载资源到个人库，再保存到工程或资源包。工程分享携带完整依赖，关闭或移除订阅不会删除本地数据。

## 验收要求

- 干净检出无需资源目录即可完成 `npm test` 和 `npm run build`。
- 远程目录、资源图和音频依赖均验证 schema、ID、大小、哈希和预算。
- 官方库与补充库可同时订阅；单个库失败不会清空其他库。
- 浏览器可完成搜索、试听、下载到个人库、保存、重开和导出。
- 新增音源先在资源仓库发布固定版本，再更新主站目录地址。

历史迁移记录不再作为开发步骤；后续维护只按 [内置资源维护流程](builtin-resource-maintenance.md) 和 [多音库交接](handoff-multi-libraries.md) 执行。
