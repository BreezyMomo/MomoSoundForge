# 不可变资源与共享音频架构

用户确认于 2026-11-07。本文件记录本轮改造的目标与约束；实现和验收进度在文末更新。项目尚未发布，不做旧工程或旧库迁移；用于生成内置资源的输入由构建工具转换，不能直接删除。

## 身份与编辑

1. 音频数据、合成器定义、乐器绑定和可复用声音内容分别拥有内容 ID。内容对象不可变；发声内容修改后得到新 ID，相同内容得到同一个 ID。
2. 音频 ID 根据确定的 PCM 编码、采样率和声道计算。传输压缩、文件名和路径不参与音频身份；文件传输使用另外的字节数和 SHA-256 校验。
3. 名称、分类、说明、预览、来源与授权属于描述信息，不改变发声内容 ID。去重不得丢弃来源和授权。资源库条目可以为同一内容提供不同名称；它不是第二份声音数据。
4. 播放器、声层、音符等实例拥有独立实例 ID。多个实例共享资源，位置、裁剪、循环、速度、音量、效果和参数属于实例。不得通过修改共享对象改变别的实例。
5. 编辑器允许有尚未封存的可变草稿。保存、分享或持久化时封存内容，得到新 ID；只把当前编辑对象改为引用新内容。撤销恢复旧引用，不批量更新其他作品。
6. 合成器定义和生成结果分别标识。算法及参数定义属于合成器；实际参数值、随机种子、时长等属于声音实例。保存下来的渲染音频使用普通音频 ID；临时试听只是缓存，不自动增加个人资源条目。
7. 同一 ID 不得对应不同内容。导入和磁盘读取必须校验，发现冲突明确失败，不能悄悄覆盖或改名绕过。

## 资源图、文件与解析

- 乐器绑定按 ID 引用音频或合成器；组合引用声音内容；大音频不嵌进每个乐器／作品文件。依赖由统一资源解析层获取。
- 编辑器／渲染器可以使用展开的工作快照，不能把它误当成磁盘存储格式；保存时必须收集依赖并去重。
- 内置和个人资源共用内容 ID 规则。内置目录的展示 ID、资源库条目 ID、实例 ID 与内容 ID 是不同职责，不用文件 URL 当身份。
- 当前原生保存格式使用共享对象表和依赖引用。所有引用必须可解析，循环、过深嵌套、重复冲突及资源预算超限都要拒绝。
- 内容对象可以由个人库、工程包或内置音库提供；导入已有内容时复用，不再写一份。打开工程不等于收藏到个人库；未连接个人库也能使用工程所带资源。
- 元数据和音频的校验各自独立；不把“听起来相似”当作完全相同的数据。

## 分享与离线编辑

- 默认分享的是可继续编辑的工程／资源，必须包含完整依赖闭包，每个对象只打包一次。不能只带当前曲子演奏过的几个音符，却声称乐器已经可以离线编辑。
- 内置录音可通过固定传输描述按需取得；分享时把依赖收齐。大音频保留为独立包内文件，打开时按需解码，不能通过扩大实时渲染 PCM 预算来塞入整套钢琴。
- 导入先完成格式、内容哈希、依赖闭包和预算校验，再原子接入当前工程。失败或取消不修改工程，也不污染个人库。
- 合成器公式与必要参数定义必须随包携带。包记录渲染契约及随机种子等条件；当前不建设旧引擎兼容层。

## 个人资源库与删除

- 磁盘库将目录条目、不可变定义和共享音频分开存储。同一内容对象只写一次；编辑后保存新内容，旧内容不被覆盖。
- 删除条目只取消其在库中的展示，不连带删除被其他定义、工程或撤销记录引用的内容。当前先不自动回收内容对象；以后明确设计引用检查和垃圾清理，不能以磁盘去重为由误删。
- 工程应拥有可解析的资源快照，不依赖用户在原开发机上的绝对路径或某个仍存在的库条目。

## 本轮改造顺序与验收

1. 建立内容 ID、不可变对象图、共享音频和完整依赖包的基础实现。
2. 接入原生工程／资源保存、导入和 AI 文件流程；工作草稿与持久化内容身份分开。
3. 个人库改为共享对象存储；内容相同复用，内容变化只更新当前条目所引用的新对象，不改别的作品。
4. 转换所有内置生成数据，保持声音及作者映射，更新工具、目录、文案和交接。
5. 验证：相同音频跨多处只存一次；改名不改音频／合成器身份；发声定义修改产生新身份；两个实例互不影响；重复导入不重复写内容；同 ID 异内容拒绝；分享完整乐器后断网添加未演奏过的音符仍可播放；删库条目不破坏已有工程；试听、波形与导出的实际声音保持一致。

## 实际格式与入口

- 工作副本：仍是经过模型校验的展开结构，现有播放器、裁剪、循环、速度、参数、音符与撤销操作保持独立。这里的播放器／乐器绑定 ID 是局部实例别名，不是不可变定义 ID。
- 持久化定义：`momo.resource-graph/v1`，记录 `renderContract: momo.engine/1`。对象由规范化 JSON 的 SHA-256 标识；`synth-…` 和 `instrument-…` 是实际不可变定义 ID，其他结构节点使用 `node-…`。乐器对象纳入绑定音频的内容 ID，因此只改绑定录音也会产生新乐器身份。
- 描述信息：独立 `annotations` 保存名称、来源、授权与绑定别名。改名不改变内容图 ID；改变实例 ID 可能改变固定种子的交替录音选择，不能为了去重随意重排或重写实例 ID。
- 音频：`audio-<SHA256>` 标识 MSA1 格式（16 字节头、整数采样率／声道数／帧数、按声道排列的小端 Float32 PCM）。`momo.audio-reference/v1` 引用它；`frameLimit` 保留已有演奏片段边界，不截短实际共享录音。
- 个人文件夹：`index.json` 使用 `momo.sound-library/v2`；`resources/*.sfresource` 是条目快照清单，`objects/*.json` 是共享定义，`audio/*.pcm.gz` 是共享音频。目录条目的 ID／版本用于保存冲突检查，`contentId` 指向不可变内容，两者职责不同。
- 下载的 `.soundforge` / `.sfresource` 是 ZIP 包：`manifest.json` 和 `audio/<audioId>.pcm.gz`。与文件夹内的清单文件不同，下载包包含完整依赖，可以独立移动。音频逐份压缩，不能先把完整钢琴的近 947 MiB PCM 全部积存在 JSZip 中。
- 浏览器共享音频池：IndexedDB `momo-shared-audio` 按 audioId 缓存压缩内容，为导入工程和打开的文件夹资源提供可重载的依赖；不创建个人资源库条目。普通浏览器缓存可能被清理，正式备份仍是下载包／文件夹。
- 内置：生成的声音文件也是内容图；目录 `audio` 表将 audioId 映射到固定传输文件。已有 WAV16 录音保留原传输格式，其他 PCM 使用无损压缩；传输字节 SHA 与 PCM 身份分开校验。完整录音目录继续保留作者映射和许可。
- AI：在线编辑协议中的 JSON 是当前编辑会话工作副本；可交付文件必须使用打包接口。离线 CLI 生成／打开新的二进制工程包；`resource-pack` 可把 AI 编写的定义 JSON 封存为资源包，不能把定义 JSON 当最终分享包。

预算：清单／定义图 16 MiB、打包后 768 MiB、完整依赖 PCM 1.5 GiB、最多 2048 个独立录音。单录音仍最多 5,760,000 帧、双声道；**实际渲染 PCM 24 MiB 的限制保持不变**。这些是不同阶段的预算；包内全琴键存在，不等于同时解码全琴键。解包检查重复路径、解压预算、对象哈希、依赖完整性和模型约束后才接入工作副本。删除目录条目不回收对象。

主要实现：`src/sharedAudio.ts`（PCM 身份、解析及缓存）、`src/resourceGraph.ts`（封存／展开）、`src/resourcePackage.ts`（完整依赖文件）、`src/folderLibrary.ts`（文件夹共享对象）。不得重新引入“保存时只收集已演奏音符”的便携格式。

## 2026-11-07 本地验收

- `npm test`：46 个测试文件、381 项通过；资源测试组：6 个文件、16 项通过；`npm run build` 通过。
- 最终静态部署目录校验通过：274 个声音，站点 650.7 MiB；运行音库清单共 1,314 个文件、644,122,899 字节（约 614.3 MiB）。这是本地构建结果，未发布。
- 274 个内置声音已转换为内容图。对比转换前的原始项目，274 个默认渲染及 74 个音区在力度 1、127 下的渲染，共 422 份 WAV 字节完全一致；默认波形与时长也一致。这是数据一致性验证，不代表其他乐器已完成音源品质替换。
- 真实浏览器完整钢琴验证：222 份录音全部打包，压缩包约 174.12 MiB；导入后禁止网络访问，原曲 PCM 一致，并能新增此前未演奏的 C8 重弹和 A0 轻弹；草稿恢复及实际音频 Worker 渲染通过。
- 真实编辑器通过“打开工程”和“保存工程”完成含合成音与采样的工程往返，下载文件再次离线渲染得到相同 WAV。
- 自动测试覆盖共享录音去重、定义变更产生新身份、改名保持身份、篡改／缺失依赖拒绝、重复保存复用以及删目录条目保留共享对象。
- 本地验证产物在忽略的 `test-results/immutable-*` 下，不作为发布输入。发布只能使用当前构建的目录及分发校验工具，不能误用历史候选目录。

当前边界：首次打包完整乐器需要取得所有依赖，可能比试听慢且文件较大；浏览器共享缓存不替代正式备份。AI 批量导出仍受自身 128 MiB 总预算约束，完整大钢琴可使用编辑器的正常工程保存。自动垃圾清理和其他乐器的整套品质替换尚未完成；远端音库已在后续发布工作中上线，见上方发布记录。
