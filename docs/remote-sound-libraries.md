# 多音库规则与实施

2026-11-07 用户确认。目标：用户可以订阅多个音库，官方库与团队／个人库采用相同协议；GitHub Pages 只是当前托管方式，也可使用 HTTPS 静态服务、对象存储或 CDN。本文件先记录约束，完成情况与验收另行记录，不把计划当作已实现。

## 身份、内容和来源

- 音库拥有稳定 `libraryId`，目录地址只是获取位置。修改地址必须确认新目录仍属于同一音库；换成另一个音库应新增订阅。
- 目录条目 ID 与内容 ID 分开。音频和发声定义延续不可变内容 ID；内容修改产生新 ID。目录名称、分类、说明和授权不参与内容身份。
- 分类与仓库不绑定：一个库可有多个分类，同类资源可以来自不同库。各库统一搜索，允许按来源筛选。
- 相同内容多来源不重复存储音频；来源和许可仍保留，不因去重丢失。重名不等于相同内容。
- 更新目录不修改已打开的工程。停用／移除订阅不删除本地文件、共享音频和现有工程。

## 目录和加载

- 远端目录采用明确版本的 JSON，包含音库身份、条目元数据、资源图和音频传输描述。各库必须包含条目的完整依赖，不依赖另一个订阅是否开启。
- 地址通过用户订阅配置，不能由导入的工程偷偷添加。订阅属于界面／环境设置，不进入工程及撤销记录。
- 官方库默认订阅；基础合成器及程序预设保留离线可用。其余官方素材走与外部库相同的目录／下载流程。
- 目录独立刷新；某个库失败保留此前有效目录，其他库继续可用。显示正在刷新、可用条数及错误，不把加载失败显示成空库成功。
- 验证 schema、字段、ID、文件大小、哈希、完整依赖及解压预算；只加载数据，远端不能提供可执行脚本。公开音库不携带账号凭据。
- 下载／保存／分享带完整依赖，包括乐器尚未演奏的音符。暂存试听不是正式本地备份。
- 同内容可在不同服务托管；跨域服务需允许 CORS。每个库独立检查容量，不能把多个地址描述为无限免费空间。

## 发布与维护

- 先发布不可变资源文件，再更新目录；旧目录仍引用的文件不能提前移除。
- 发布工具生成目录及哈希，禁止手写哈希或复制旧目录冒充新发布。
- 维护源码、映射、许可和锁文件与运行发布分离；大型音频不得进入 Git 历史。沿用 [内置资源维护流程](builtin-resource-maintenance.md)。
- 第一阶段提供订阅管理、统一展示、完整资源下载和静态音库发布工具；不建设账号系统、远端上传 API、自动垃圾回收或后台自动替换作品内容。

## 必须验收

两个不同地址同时可用；同分类跨库检索；重名不同内容不覆盖；重复音频复用；坏目录／错误哈希／缺少依赖拒绝；单库失败隔离；刷新竞态和移除中的请求不恢复订阅；地址更换保持音库身份；保存分享后断开音库仍可新增乐器音符。真实浏览器检查管理入口、筛选、试听、保存和错误提示。

## 已落地的数据约定

目录 `momo.remote-sound-library/v1` 包含 `libraryId`、`name`、`entries`、`audio`。它和构建工具使用的 `manifest.json` 完整性清单、个人文件夹的 `index.json` 是不同格式，不能互换。

- 条目：`id`（目录内唯一）、`contentId`（资源图根 ID）、`name`、可选的中英文 `names`、`kind`、`category`、`description`、`preview`。`file`、`sha256`、`bytes`、`decodedBytes` 指向 gzip 压缩资源图。下载后再次验证图根、条目 ID、类型及全部定义哈希。
- 音频：`audioId`、采样率、声道数、帧数和传输描述；`pcm` 是规范 MSA1 浮点 PCM，`wav16` 用于复用现有官方录音并保留明确增益。音频内容 ID 与传输压缩哈希分开。
- 文件路径只允许目录下的普通相对路径，拒绝上级目录、凭据和外部跳转。目录与文件读取均有限制；不能用远端内容突破工程预算。
- 最多 32 个订阅，每个目录最多 5,000 个条目、4,096 个音频描述，目录 8 MiB；资源图最多 16 MiB；单音频传输／解压最多 48 MiB，并遵循最多 5,760,000 帧、双声道。图的完整依赖仍遵循原有 2,048 个录音及 1.5 GiB PCM 总预算。
- 试听按需注册来源；用于作品和下载时收齐完整依赖并缓存，之后不依赖订阅仍然存在。完整大乐器第一次使用可能耗时较长，不把“正在读取”伪装成已经完成。正式离线备份仍使用本地文件夹或分享包。
- 远端重复内容在列表合并为一张卡片，展示来源名称；按具体来源筛选时只使用那个来源。下载到本地库前检查已有 `contentId`，不因来自另一个地址再增加同一内容条目。不同名称／许可保留在各目录及资源图中。
- 首次默认订阅由部署地址确定；后续用户添加／改地址即时生效，无需重新构建网站。刷新目录不会自动给现有作品更换内容。
