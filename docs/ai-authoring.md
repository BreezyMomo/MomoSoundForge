# AI 创作与素材检索

顶部「AI 工具」用于连接你自己的 AI 客户端。它与 TextureForge 的入口方式一致：安装创作 Skill、启动本机连接服务、连接当前页面、把 MCP 配置交给客户端。应用不内置聊天模型，也不要求在网页里填写模型密钥。

## 第一次使用

1. 打开「AI 工具」，下载 ZIP，解压到 AI 客户端的 skills 目录；支持目录选择的浏览器也可以直接选择该目录安装。已有同名文件发生变化时会先备份。重新加载客户端中的 Skill。
2. 点击「复制说明」，交给 AI。Skill 自带 Node.js 22+ 可运行的连接服务和离线原生引擎，不要求安装源码或 npm 依赖。AI 按说明启动服务；不同编辑器地址需分别传 `--allow-origin`。
3. 点击「连接当前页面」。把面板生成的 MCP 配置添加到支持 Streamable HTTP 和请求头的客户端，刷新工具。配置含本次服务的连接凭据，不要公开分享。服务重启后需重新复制配置。
4. 向 AI 描述想做的声音，例如「在当前拾取音效里增加轻巧的三音旋律，保留原来的音效，做完让我试听」。AI 可以查实际声音库、读取节点与真实乐器音域、修改音符和后处理、生成试听。

AI 的每批编辑只占一次撤销。你手动编辑后，旧快照不能再用于写入；AI 必须重新读取。关闭面板保持连接；点击断开或刷新页面会结束连接。多页面通过页面 ID 区分，Skill 要求先选择目标作品。

## 内置能力

- 原生创作：声音层、分组、时长、后处理、自动化、组合控件及乐器音符。试听与离线 WAV 使用同一引擎；采样随工程携带。
- 旋律设计：适配 melody-design 的方法、知识索引和 31 组原创 A/B 配方，可生成可编辑工程。不会把基础振荡器冒充真实乐器。
- 素材发现：优先查询已有声音库；联网工具检索 Freesound 的 CC0 候选，返回时长、来源、作者、许可及试听地址。下载量与评分只作筛选线索，不代表试听判断。
- 素材入库：明确选择后可导入 Freesound 的 MP3 **试听版**；原始录音从原站获取后通过文件导入。采样属性显示质量和来源，工程保留元数据，「导出作品素材来源」生成来源清单。未记录来源的采样会明确标注，而不是推断许可。
- 离线交付：CLI 支持新建、修改、校验、原生 WAV 渲染、获取指定内置声音、PCM WAV 导入、多采样乐器清单和原创旋律配方。详细用法在安装包 references/offline.md。

Kenney、OpenGameArt 等来源的查找与许可核对写入 Skill 的工作流程；当前自动联网检索适配器只接 Freesound CC0，不宣称实现了这些站点的自动采集。外部网站页面结构或网络限制可能使检索失败，此时会说明失败原因，不能凭空补结果。该工作流参考 vibe-motion/sound 的用途，未复制其脚本、代理配置或推广内容。

## 运行与验证

源码开发可运行 `npm run ai:serve -- --allow-origin http://127.0.0.1:5180`。`npm run ai:build` 生成 `public/ai/momo-sound-forge.zip`；开发与生产构建都会生成该包。包内含原生引擎源码摘要和所打包依赖的许可。更新应用后重新下载安装包。

服务只监听 127.0.0.1，校验 Host、Origin 和随机凭据；每个浏览器页面使用独立会话。工具不提供任意脚本执行或任意本机文件读取。个人库查询由客户端按用户需要调用。素材检索只发送搜索词，不上传工程。导入、渲染和工程格式均有资源预算。

音频指标与乐器覆盖检查用于发现问题，不等于 AI 已经听过声音。客户端不能处理音频时，应在编辑器里实际试听。视频参考目前提供时间范围和标记，不提供视频画面理解。MCP 直接导出提供 WAV 与原生工程，其他编码格式继续使用应用统一导出面板。
