## 已完成的使用流程

1. 顶栏 **合成器与乐器** 打开独立资源编辑器。这里管理生成规则、默认参数、录音与音高的映射，不管理作品时间轴。
2. **合成器**：新建、命名、设置默认参数、试听、保存、另存、导入和导出 `.sfsynth`。当前只有 `oscillator-v1` 算法，可创建多个不同参数的定义，不是多个算法。
3. **乐器**：选择内置乐器作为起点，或新建后导入本地录音／取用当前组合已有录音。选择采样，点击“用采样创建乐器”，编辑音域、力度、演奏法、轮替、释放与循环映射。编辑表单后先点 **应用映射**，再 **保存定义**。导出 `.sfinstrument` 携带录音。
4. **创建声音层**：合成器创建 0.5 秒的合成播放器；乐器创建 2 秒的空谱播放器，之后在音符编辑器添加音符。试听乐器时生成的临时音符不保存到乐器定义。
5. 已有合成／乐器声音层的属性中有 **选择合成器／乐器**。合成器选择应用新默认参数；乐器选择替换映射并保留原音符。声层位置、读段、速度、循环、播放时长、混音与自身效果保留，一次撤销恢复。没有录音覆盖的音符保留并提示修正。
6. 做好的声音仍由“存入声音库”保存为音效。**保存定义**和**保存声音**是两条不同流程。

## 数据约定

- `SynthDefinition`：`schema: momo.synth/v1`、`id`、`name`、`algorithm`、`defaults`。定义没有播放器时长和父级编排信息。
- 合成播放器：`player.type = synth`，`player.synth` 携带完整定义快照。现有 `player.frequency/wave/...` 是本次声音实际参数；`synth.defaults` 是创建时使用的默认值，渲染实际参数，不在每次渲染时重新覆盖。
- `InstrumentDefinition`：`schema: momo.instrument/v1`、`instrument`、`assets`，沿用已有便携乐器包格式。`instrument.regions` 保存录音映射，不带音符。
- 乐器播放器：`player.score.instruments` 保存定义快照，`player.score.notes` 保存演奏事件；录音放在最近一层组合的 `assets`。原生工程仍是 `momo.soundforge/v4`。
- 插入或绑定时重映射录音 ID；保存剔除未用录音。定义文件及原生工程都不依赖开发机路径或本机数据库。
- 定义是独立副本，编辑资源库定义不会联动已有作品。要更新已有播放器，必须显式选择定义。播放器参数调整也不改资源库。
- “选择定义”与“更换内容”不同：选择定义仅适用于同类型播放器，保留其演奏和处理；更换内容整体换掉 `player`。不要把两个入口接到同一个替换函数。
- 对已有多乐器谱面执行“选择乐器”会将全部音符映射到所选单一乐器，并保留其他音符字段。定义编辑器每份定义只含一个乐器；既有谱面仍可包含多个乐器。

## 代码入口

- `src/synthesizers.ts`：类型、内置振荡器、参数范围、严格校验、波形采样函数。只允许引擎内置算法，不执行导入文件中的代码。
- `src/soundDefinitions.ts`：定义校验、创建空播放器、临时试听、同类型绑定、从实例提取合成参数。
- `src/definitionStorage.ts`：独立 IndexedDB `momo-sound-forge-definitions` v1；`definitions` 存内容，`index` 存列表元数据，保存采用同一事务。不要把定义管理操作加入作品撤销记录。
- `src/DefinitionEditor.tsx`、`src/definition-editor.css`：资源窗口。使用 Workbench Dialog；不要换回原生 `dialog.showModal()`，否则共享选择框的 portal 会被顶层模态窗口挡住。布局样式放 `@layer utilities`，兼容共享组件隔离规则。
- `src/ScoreEditor.tsx` 的 `definitionOnly`：复用映射编辑，隐藏音符与多乐器导入入口。表单修改需“应用映射”才写入草稿。
- `src/App.tsx`：顶栏入口、属性绑定入口、试听、导入录音、插入与一次撤销。打开时记录作品及组合路径，过期上下文禁止写入。
- `src/model.ts`：合成定义进入 `CONTENT_KEYS`，创建／读取时校验；非合成播放器剔除该字段。v4 未显式带定义的合成播放器补内置默认定义，实际声音参数保持不变；不支持旧 v3 工程。
- `src/engine.ts`：调用可信算法采样函数，包络／滤波等现有处理不变。试听、波形、导出继续共用渲染器。
- `src/definitionMessages.ts`：中英文语义文案。
- `tests/definitions.test.ts`：隔离与便携保存、IDB、算法和录音校验、空谱／临时试听、绑定参数保留与音频 ID 重映射。
- `tools/build-builtin-library.mjs`：构建指纹包含 `synthesizers.ts`。内置工程已重新生成目录和哈希；不要手改 catalog 哈希。

## 验证与运行

```sh
npm ci
npm test
npm run build
npm run dev -- --port 5202
```

Node.js 22+；固定 Workbench 包位于 `vendor/`，不需要其他仓库。首次构建会生成约 415 MiB 的内置资源，需等待；生成目录被 Git 忽略。请运行 npm 脚本触发 pretest/prebuild，而不是在缺失资源时只运行 Vitest/Vite。

本轮完整测试：33 文件、302 用例通过；生产构建与静态站点资源检查通过（287 个声音）。真实浏览器已检查：新建合成器→保存→创建声音→修改定义不改变已有声音→显式绑定→撤销；内置乐器提取→空谱→添加音符→换乐器保留音符且提示音域缺口→撤销；当前录音→新建映射→保存→试听→导出并重新导入。下拉菜单遮挡问题已修复。

资源库按浏览器和 origin 隔离；换端口后看不到本机定义属正常行为，可导出／导入转移。测试用本机定义不在 Git 中。

## 后续边界与建议

- 目前定义是 **一种可信算法 + 默认参数**；没有用户编写公式或节点连接的算法编辑器。新增不同参数结构的算法时，应将 `SynthDefinition` 改为按 algorithm 区分的联合类型，同时扩展校验、实际播放器参数、渲染、编辑器和回归测试。仅增加下拉选项不够。
- 乐器映射目前只接受录音，不接受任意递归播放器或合成器。不要在未设计资源预算和时间规则时直接开放。
- 映射页面复用了完整高级表单，仍包含 MIDI 和帧数。下一步优先做直观音名、覆盖范围与试听引导，逐步收起精确设置，降低首次创建门槛。
- 内置乐器按现有音区条目提供，尚未聚合为全音域大乐器。导入、保存及导出继续受既有资源预算约束。
- 本机定义库尚无删除／回收站、分类、批量导入和跨设备同步。新增管理能力须保持与作品撤销分离。
- “使用当前作品录音”取打开窗口所在组合的直接资产，不递归收集所有嵌套组合。
- 合成算法选择不自动清除已有实例自动化和组合控件；当前只有同一种参数结构。将来跨算法切换必须制定失效参数绑定处理。
- AI 的工程 capture/patch 可携带 `player.synth`，尚未新增独立定义库 CRUD MCP 工具。不要向用户宣称 AI 已能直接管理本机定义库。
- 此分支未合回 main；接手前先看 `git status` 和远端分支状态，避免覆盖其他人的工作。
