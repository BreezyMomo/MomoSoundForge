# 完整音乐制作

本流程用于背景音乐、钢琴曲、短配乐、多声部片段和需要“像一首音乐”而不是“像一串音符”的作品。它使用 MomoSoundForge 的可编辑音符、乐器、组合和渲染能力，但先完成音乐设计，再落地到工程。目标是让用户能听出动机、和声方向、段落变化和结束感。

## 什么时候使用

满足任一条件就走本流程：

- 用户说“作曲、编曲、背景音乐、钢琴曲、主题音乐、治愈 BGM、战斗音乐”等；
- 作品超过一个乐句，或需要 8 小节以上；
- 需要旋律、低音、和弦、琶音、铺底等两个以上音乐角色；
- 用户说“现在太简单”“像练习曲”“需要更完整、更像歌”。

单次提示音、短 UI 音和 2–5 个音的动机仍走 `melody.md`，不要为短音效引入完整曲式。

## 核心原则

1. **先定结构，再写音符。** 先确定小节数、拍号、BPM、调性、段落和循环边界，再生成事件。
2. **先写动机，再发展动机。** 旋律必须有可复述的节奏或音高细胞；后续段落通过重复、移调、节奏压缩、延长、回应和收束发展它。
3. **每个声部有职责。** 主旋律负责记忆点，低音负责根音与方向，和声/琶音负责色彩和脉冲，铺底负责空间。不要让所有声部每拍同时变化。
4. **和声要有方向。** 段落至少有稳定、离开、回归三种功能；结尾要有明确终止或有意的开放悬停。
5. **变化要可听见但不混乱。** 每 2–4 小节至少改变一个音乐因素，同时保留动机身份；不要靠随机音高制造“丰富”。
6. **音符必须为真实音源负责。** 写入前检查音域、力度层、演奏法、持续录音和释放尾音；缺少覆盖就改写方案或明确替代，不静默越界。
7. **试听是质量门槛。** 数值合法不等于音乐成立；至少试听开头、段落转折、高潮/回归和结尾，确认没有机械重复、拥挤、突兀断尾或过载。

## 制作流程

### 1. 音乐简报

从用户描述提取或合理推断：用途、时长、是否循环、情绪、画面/游戏状态、主要乐器、参考气质和不能出现的特征。信息不足时用少量默认值继续，不把新手强行问成编曲师。

先给出可审阅的简报：

```text
长度：8 小节，4/4，72 BPM，约 26.7 秒
调性：C 大调（明亮但保留一点悬念）
结构：A 4 小节 → A' 4 小节，末拍留尾音
角色：钢琴旋律 / 左手低音 / 分解和弦
发展：A' 提高旋律最高音，延长第 8 小节，最后回到主和弦
```

### 2. 曲式与和声骨架

先写每小节的功能和和弦，不急着填满音符。常用的短配乐骨架包括：

| 结构 | 作用 |
| --- | --- |
| I–V–vi–IV | 熟悉、流动、适合温柔背景音乐 |
| I–vi–IV–V | 叙事感和回归感较强 |
| vi–IV–I–V | 从内省开始，再逐步打开 |
| i–VI–III–VII | 小调抒情，适合克制的忧伤 |
| I–IV–ii–V → I | 先展开，结尾形成清楚回家感 |

这些是起点，不是自动套用规则。低音优先落在根音或有意的经过音，避免每小节根音都完全相同。和弦重复时至少改变一个因素：转位、节奏、音区、力度或琶音方向。

### 3. 动机设计

先写 1–2 小节动机，记录三件事：

- 音高轮廓：上行、回落、邻级或小跳；
- 节奏细胞：例如「长—短短—长」或带一个休止；
- 句尾行为：停在主音、三音、属音或悬停音。

动机通过以下方式发展，至少选择两种：

- 原样重复但更换和声；
- 整体移调或局部级进；
- 末尾增加回应音；
- 节奏压缩/延长；
- 音域抬高或降低八度；
- 留出更长休止，让下一句回答。

禁止只复制同一个一拍音型 16 次来充当完整旋律。

### 4. 声部安排

默认按职责建立独立声部或同一乐器的明确音区：

1. **主旋律**：每小节保留呼吸点，避免全程 1/4 拍填满；句尾可延长。
2. **低音**：根音、五度、经过音和八度交替；在段落转折处改变走向。
3. **和声/琶音**：用三和弦/七和弦的转位，错开主旋律起音；不要每次都同时起音。
4. **铺底或装饰**：只在需要时出现，用长音、稀疏回应或高音色彩补空间。

钢琴示范至少应有旋律、低音和一种和声运动；单音旋律加一串同节奏根音不算完整编曲。

### 5. 表现与发展

为不同段落设置可听见的表现变化：

- A 段：中低力度、较窄音域、疏朗节奏；
- A' 或 B 段：增加内声、提高最高音、改变琶音方向或扩大力度；
- 回归：减少层数、回到主音区，给出终止或有意的开放尾巴。

力度使用连续的层次，不要每个音随机抖动。相邻重复音可有轻微力度和轮替变化，但同一句的重音必须稳定。

### 6. 落地为音符事件

把小节/拍转换为工程音符时：

- 原生乐器音符使用拍；先固定 BPM，再换算秒；
- 每个音符写明 MIDI、起点拍、时值拍、力度、乐器和演奏法；
- 和弦音可以同拍开始，但琶音应有明确的 1/8 或 1/16 拍错位；
- 释放尾音不计入按住时值，最后一小节要预留尾音空间；
- 总作品窗口至少覆盖最后一个按住时值和自然尾音；循环时单独检查接缝。

推荐的内部草稿结构：

```json
{
  "bpm": 72,
  "meter": "4/4",
  "key": "C major",
  "bars": 8,
  "sections": [
    {"name":"A", "bars":[1,2,3,4], "harmony":["C","G/B","Am","F"]},
    {"name":"A_prime", "bars":[5,6,7,8], "harmony":["C/E","G","F","C"]}
  ],
  "voices": {
    "melody": [{"midi":60,"beat":0,"duration":1,"velocity":72}],
    "bass": [{"midi":36,"beat":0,"duration":2,"velocity":48}],
    "伴奏": [{"midi":60,"beat":0,"duration":0.5,"velocity":44}]
  }
}
```

这只是编曲草稿，不是可直接导入的最终工程。落地时仍须使用当前 schema、现有乐器映射和资源快照；不能把 `scale` 或 `key` 交给引擎后期待它自动重写音符。

### 7. 试听与自检

渲染后按以下顺序检查：

1. 只听旋律：是否有可记忆的动机和呼吸；
2. 只听低音/和声：是否能感到和声方向而非机械打拍；
3. 听全编曲：旋律是否被低音或混响盖住；
4. 听 A→A' 或段落转折：变化是否明显且仍像同一首曲子；
5. 听结尾和循环点：是否自然收束，没有尾音被截断；
6. 检查峰值、静音、超出音域、缺少映射和渲染预算。

如果仍然“太简单”，按顺序增加：**段落对比 → 和声转位/经过音 → 旋律回应 → 内声或装饰**。不要第一反应是增加更多随机音符、混响或音量。

## 交付与迭代

交付至少包含：可编辑工程、音符/声部说明、试听 WAV，以及一段简短的结构说明。向用户明确：主旋律在哪里、和声如何发展、哪个位置是高潮或回归。

用户反馈“更丰富”时，先判断是缺少曲式、和声、旋律发展、层次还是表现力，再只改主要问题。生成候选时保留相同 BPM、长度和主音区，让用户能真正比较版本。
