## 用户得到的行为

- 在资源库选择“乐器”，搜索 Kawai，可直接选用一整架钢琴。标准 88 键 A0–C8 均有映射，不需要逐个添加音区。新建音符默认 C4。
- 根据音高、力度选择实际录音，并在松开音符时播放对应的松键声。完整工作录音不截成 4 秒；长按仍受原始录音自然衰减与剩余时长限制，没有虚构持续循环。
- 222 份录音仍是可独立选择的录音资源：138 份起音、84 份松键。没有新增“乐器包”界面概念。
- 作品保存、声音资源保存、变体工程导出以及 AI 工程导出会携带当前演奏所需音频。已保存的当前音符可离线重放；新增琴键、改力度、延长音符可能需要从站点补充录音。
- 乐器定义保存／导出保留全部绑定和内置引用，不会下载全琴键音频。它不是一个全琴键离线包；编辑器已明确说明这一点。浏览器自动草稿也不承诺提前下载所有依赖。
- `example-expanded-piano` 已改用新钢琴，资源修订为 2。历史 `example-piano-window-light` 是内嵌声音组合快照，仍保留旧声音，不能宣称全部历史示例都已换源。

## 来源和转换

来源为 [VCSL 官方仓库](https://github.com/sgossner/VCSL)，固定提交 `dfcf4a4918771eee884b96ad4493de82ef84daf6`，映射 `Chordophones/Zithers/Grand Piano, Kawai.sfz`。固定提交的 README 是 CC0 使用说明，已随库保留；来源 SHA256、Git blob、作者参数和转换参数见 `samples/vcsl-kawai-20261107/manifest.json`。

复现流程：运行 `node tools/prepare-vcsl-piano.mjs --download` 获取校验过的原件，再使用安装了 `tools/audio-audit-requirements.txt` 的 Python 运行 `tools/convert-vcsl-piano.py`。完整工作 WAV、映射和许可属于构建输入；`originals/` 是可复现的本地原件缓存，本轮未纳入 Git。旧素材没有删除。

工作格式为 48 kHz 双声道 PCM16，保留完整尾音，最长约 43.669 秒。为保留安静原件的量化精度，每份工作 WAV 暂存到 0.5 峰值；区域增益精确抵消该暂存增益，再应用作者 volume 和全乐器统一 -7 dB 余量。这不是逐音符响度拉平，不允许在后续转换中丢掉补偿增益。

作者起音和松键录音的键域、力度边界并不相同。构建器按两者的交集划分成 193 个原生区域，保留独立松键根音、调音、offset 和增益。`rt_decay` 按按住秒数衰减松键声；不能按录音播放经过时间计算。参考 [SFZ rt_decay](https://sfzformat.com/opcodes/rt_decay/)。作者延伸到 C♯8，当前产品明确只提供标准键域至 C8。

当前采用原生线性力度响应与包络适配，不是完整 SFZ 播放器，不保证与某个 SFZ 引擎逐采样相同。没有加入延音踏板、共鸣模型或自动音高校正。技术验证不等于对每份录音完成专业主观听审；用户不承担判断音准和乐器真实性的义务。

## 引擎和存储边界

`SampleAsset.reference` 使用 `momo.builtin-sample/v1`，只含内容哈希、固定文件名、长度、完整帧数和增益步骤，不允许 URL 或本机路径。`channels: []` 代表尚未物化；有内容时是已经物化的源前缀，完整时长仍由 reference.frames 决定。

`prepareSamples.ts` 在渲染前递归准备当前音符依赖，使用和渲染器一致的排序、轮替与 player.noiseSeed。按音高变调、offset、按住时间、释放和循环边界计算必需帧数，松键声独立处理。音符完全播放模式不加载旁路的松键录音。仅修改准备副本，不把网络加载写入编辑历史。取消的旧任务即使完成下载也不能覆盖新试听。

下载校验压缩大小、SHA256、展开大小和固定 WAV 布局；压缩缓存 12 MiB，解码顺序执行。当前传输仍下载整份压缩录音，再只保留需要的 PCM 前缀，不是 HTTP 流式片段下载。

单工程解码 PCM 总预算仍为 24 MiB，普通内嵌资产上限仍为 64；直接资产字典最多 512 项，以容纳轻量引用，单乐谱区域最多 512 项。需要的声音超限时在下载前报错，不自动削减力度层或截尾。单录音帧数沿用引擎 5,760,000 上限；独立内置录音加载器从原 30 秒限制统一到该上限。

`portableResource.ts` 负责保存边界；渲染器、浏览器保存、文件夹声音资源保存及 CLI 都复用同一准备函数。原作品中的嵌入 PCM 不会因库更新而改变。已嵌入前缀足够时不请求网络；改成长音时按引用重新补齐。
